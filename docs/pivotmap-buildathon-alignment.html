The idea

A constraint arrives after the code is written — a dependency is banned, a vendor is dropped. The developer needs three answers before touching anything: what actually violates this, what breaks if I rip it out, and what can I leave alone. Today that is manual archaeology: git log shows what changed but not why, and grep finds the banned import but not the three modules built on top of it.

PivotMap is one new command — entire graph pivot — that splits the repository into four populations and prints the graph edge behind every single verdict, so a reader can check the claim instead of trusting it.
VerdictMeaningAction
INVALIDATEDHas an IMPORTS/CALLS/CONSTRUCTS edge reaching the prohibited dependencyReplace
AT-RISKReachable from an invalidated file, breadth-first, capped at depthRework + retest
SAFENo path found to anything invalidatedLeave alone
UNREACHEDInventory-only language — the parser never checked itManual review
No LLM produces a verdict. The interpretive step — a sentence like "we can't send customer data through Library X" becoming the package name — stays outside the binary. That is not a style preference: the plugin's own doctor asserts no_egress=true, and a model call inside would make its own diagnostic lie.

What we built today

Shipped File roles — every file classified PRODUCTION | TEST | TEST_FIXTURE | GENERATED | VENDOR | UNKNOWN from signals that cannot be argued with: a vendor/ segment, a testdata|fixtures|mocks segment, the _test.go suffix, or the Code generated ... DO NOT EDIT. header read from the file itself.
The role never changes a verdict — only how the report is grouped and ranked. 187 at-risk test files that all resolve to one go test ./internal/sem were burying the 8 production files somebody actually has to open. The fix is to rank, not to drop: a deleted result is one nobody can audit.
Shipped --format plan — emits pivot-plan/v1, an agent work order rather than a graph dump. Every file becomes exactly one work item, sorted before ids are assigned so reading top to bottom is reading execution order. 
INVALIDATED -> REPLACE_OR_REMOVE      P0 = direct violation in shipped code
AT-RISK     -> VERIFY_AFTER_ROOT_FIX  P1 = violation in a test, or shipped code on a bad foundation
SAFE        -> NO_ACTION              P2 = covered by a package command, or not a change at all
UNREACHED   -> MANUAL_REVIEW
Two parts of the schema exist because of how an agent fails, not how the graph works: known_blind_spots (6) and execution_contract.must_not_claim (6).
Shipped --exclude-tests, applied before classification — not an output filter. A production file whose only route to invalidated code runs through a test comes back SAFE, because a test is not a foundation anything ships on. The excluded count is printed, because a file that was never classified is not a file that came back Safe.

The verification loop — the centrepiece

Run 1 pivot --format plan --> bounded work order (1 P0, 4 P1) | fresh agent session, no prior context executes P0 only, commits | Run 2 pivot --format plan --> re-derived from source. count must drop.

Run live against gorilla/mux with --dependency bytes. mux was the target because the constraint has to be satisfiable — banning os/exec in our own repo, or net/http in a router, asks an agent to delete the reason the code exists.

Found by the executing agent, not by a test. Its brief told it to read the cited source before editing, and it reported the line was not there. The plan instructed an agent to distrust the plan, and that is what surfaced the bug.
2. A test read ambient FORCE_COLOR fixed · 3170d58
It compared against an exact plain string, but the headline passes through ShouldUseColor, which honours FORCE_COLOR before checking for a terminal. CI sets no such variable and passes; a developer whose shell exports it sees a failure that looks real. Now pinned, verified both ways.
3. BUILDATHON.md printed an unreproducible plan id fixed · cf70f83
plan_id is a digest over head commit + constraint + depth + flags + counts, so it is built to change with every commit. Printing one in prose guarantees staleness.
The audit's replacement id was not substituted — this session did not independently reproduce it, and swapping an unverified number for an unverified number is not a fix. The claim was removed instead.

The honest limit — stated, not hidden

SAFE means "no path was found in this local snapshot". It is not proof of non-use. Calls through interfaces, reflection, or generated code leave no edge to follow. Observed concretely: impact --symbol Route.Match on gorilla/mux reports 0 callers even though Router.Match calls it through an interface. The impact command also self-reports Completeness: degraded for Go next to its own answer — a tool naming its own incompleteness. UNREACHED exists as a separate verdict for exactly this reason.
