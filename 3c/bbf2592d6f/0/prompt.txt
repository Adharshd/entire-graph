WHAT EXISTS — `entire graph pivot`, a new command in this fork.

Given a prohibited dependency it classifies every file as INVALIDATED (has an
IMPORTS/CALLS/CONSTRUCTS edge to it), AT-RISK (reachable from an invalidated file,
breadth-first, capped at --depth, default 2), SAFE (no path found), or UNREACHED
(inventory-only language, so genuinely unknown). Every verdict prints the edge that
produced it — relation, target, line, confidence. No LLM produces a verdict; the
plugin stays inside its no-egress contract. `--exclude-tests` drops test files
BEFORE classification, not as a filter over the finished report, so a production
file whose only route to invalidated code runs through a test comes back SAFE.

Source layout:
  internal/cli/pivot.go        classifier, flags, BFS propagation, JSON response
  internal/cli/pivot_roles.go  file-role classification + grouped text renderer
  internal/cli/pivot_plan.go   pivot-plan/v1 work-order emitter (--format plan)
  internal/cli/pivot_test.go, pivot_roles_test.go, pivot_plan_test.go
  registered in internal/cli/root.go and internal/cli/help.go

STEP 2 (done) — file roles, to kill the at-risk noise. Every file is classified
deterministically as PRODUCTION | TEST | TEST_FIXTURE | GENERATED | VENDOR | UNKNOWN.
Signals: a vendor/ path segment -> VENDOR; a testdata|fixtures|mocks segment ->
TEST_FIXTURE; the _test.go suffix -> TEST; a "Code generated ... DO NOT EDIT."
header read from the file itself -> GENERATED; a file the snapshot lists but the
working tree lacks -> UNKNOWN. Precedence is deliberate: vendor wins outright,
testdata/ beats the _test.go suffix (the toolchain never builds those), and the
generated probe runs only for files that would otherwise be production.

The role never changes a verdict, only how the report groups and ranks it. Text
output now leads with four counted lines — Required remediation / Production
follow-up / Test fallout / Coverage gaps — then lists production work file by file
with its evidence and collapses test fallout to ONE LINE PER PACKAGE carrying a
targeted `go test ./pkg`. Nothing is deleted: the JSON carries every file with its
role and every collapsed line carries its count.

STEP 3 (done, needs final commit) — `--format plan` emits pivot-plan/v1 JSON: an
agent work order, not a graph dump. Carries schema_version, a deterministic plan_id
(sha256 over head commit + constraint + depth + flags + counts), head_commit,
graph tool provenance, the constraint, counts (including per-priority and per-role),
and six explicit known_blind_spots each pairing a limitation with its consequence:
interface-dispatch, reflection, generated-code, safe-is-not-proof,
unreached-languages, name-matching.

work_items[] carry id (WI-0001, assigned AFTER sorting so reading top to bottom is
reading execution order), priority P0/P1/P2, action, verdict, role, path, package,
distance, root_invalidated, evidence[], agent_instructions[], acceptance_criteria[].
Action per verdict: INVALIDATED -> REPLACE_OR_REMOVE, AT-RISK ->
VERIFY_AFTER_ROOT_FIX, SAFE -> NO_ACTION, UNREACHED -> MANUAL_REVIEW. Priority:
P0 = direct violation in shipped code (blocks everything), P1 = violation in a test
or shipped code standing on an invalidated foundation, P2 = covered by a package
command, or not a change at all. validation.required_commands[] ends with the exact
pivot re-run that proves the constraint is satisfied.
execution_contract.must_not_claim[] forbids the likely failure — a confident report
of success nobody ran a command to check — and grows role-specific clauses only when
GENERATED or VENDOR files are actually present.

The BFS now tracks the true root invalidated file, so a two-hop at-risk item reports
the root that must be fixed rather than the intermediate neighbour it was reached
through.
